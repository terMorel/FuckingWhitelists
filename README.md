# FuckingWhitelists

Практический репозиторий о двух независимых способах сохранить доступ в интернет и об интерфейсе управления обычным VPN на собственном VPS.

> [!IMPORTANT]
> В проекте есть два разных контура. Их нельзя смешивать при диагностике или «упрощать» переносом в одну панель: у них разные задачи, транспорт и пределы производительности.

## Что здесь работает

| Контур | Назначение | Текущее решение | Статус |
|---|---|---|---|
| Обычный VPN | Ежедневный быстрый доступ через зарубежный VPS | Нативный Hysteria2; персональные доступы выдаёт Fucking Whitelists Control | Рабочий, основной |
| Туннель против белых списков | Аварийный доступ, когда прямой зарубежный VPN недоступен | FreeTurn/VK TURN переносит пакеты отдельного WireGuard-туннеля | Рабочий, не изменять без отдельной задачи |
| Резервные эксперименты | Альтернативный прямой транспорт | Xray/VLESS Reality и 3x-ui | Вторичный контур, не является основным VPN |

### Главный принцип

```text
Обычная сеть:
устройство ── Hysteria2 / UDP ──> зарубежный VPS ──> интернет

Строгий белый список:
устройство ── WireGuard внутри FreeTurn ──> разрешённая TURN-инфраструктура
           ──> зарубежный VPS ──> интернет
```

Hysteria2 выбирается для скорости и повседневного использования. FreeTurn — аварийный маршрут с естественными ограничениями TURN-канала; от него не следует ожидать производительности обычного VPN.

## Fucking Whitelists Control

Отдельная адаптивная панель управляет персональными доступами уже работающего нативного Hysteria2:

- создаёт отдельный доступ для человека или устройства;
- показывает QR и URI;
- ротирует и отзывает ключи;
- поддерживает срок действия;
- показывает состояние сервиса и ведёт журнал действий.

Панель **не находится в пути VPN-трафика**, не переносит Hysteria2 в 3x-ui и не получает доступ к WireGuard, Xray или сетевым правилам.

```text
VPN-трафик: клиент ──> Hysteria2 ──> интернет

Управление: браузер ── SSH-туннель ──> панель ── Unix socket
                                         ──> узкий root-broker ──> hy-access
```

Код панели находится в [`hyboard/`](hyboard/), установка — в [`deploy/`](deploy/), полная инструкция — в [`HYBOARD.md`](HYBOARD.md).

## Быстрый старт панели

Панель рассчитана на сервер, где уже существуют нативный Hysteria2, `/usr/local/sbin/hy-access` и `/etc/hysteria/users.json`.

```bash
git clone https://github.com/terMorel/FuckingWhitelists.git
cd FuckingWhitelists
sudo bash deploy/install.sh
```

По умолчанию интерфейс слушает только `127.0.0.1:28474`. Открывайте его с доверенного компьютера через SSH-перенаправление:

```bash
ssh -L 28474:127.0.0.1:28474 root@SERVER_IP
```

Затем перейдите на `http://127.0.0.1:28474`. Не публикуйте этот порт напрямую в интернете.

## Безопасность и восстановление

В репозитории намеренно нет реальных адресов серверов, паролей, SSH-ключей, Hysteria URI, WireGuard-ключей, `obf-key`, сертификатов и готовых приватных конфигураций.

Поэтому GitHub хранит код и знания, но **не является полной резервной копией сервера**. Для восстановления после потери VPS нужен отдельный зашифрованный офлайн-бэкап конфигурации и секретов. Его состав и порядок восстановления описаны в [`INTERNAL_CONTEXT_HYSTERIA2_HYBOARD.md`](INTERNAL_CONTEXT_HYSTERIA2_HYBOARD.md).

Базовые правила:

- не изменять рабочий FreeTurn/WireGuard-контур в задачах про обычный VPN;
- не заменять нативный Hysteria2 реализацией внутри 3x-ui без отдельного стенда и отката;
- перед серверными изменениями сохранять конфигурацию, пользователей и контрольные суммы;
- выдавать отдельный ключ каждому человеку или устройству;
- отзывать потерянные доступы, а не переиспользовать общий ключ;
- хранить серверные секреты только в зашифрованном хранилище вне Git.

## Локальная разработка

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[test]'
pytest
ruff check .
```

Для безопасного просмотра интерфейса без подключения к серверу:

```bash
HYBOARD_DEMO=1 hyboard
```

Откройте `http://127.0.0.1:28474`, пароль демонстрационного режима — `demo`. Деморежим использует только данные в памяти.
