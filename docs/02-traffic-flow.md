# 2. Как именно идёт трафик

[← Белые списки](01-whitelists.md) · [Оглавление](../README.md) · [WireGuard →](03-wireguard.md)

Разберём один запрос: пользователь открывает сайт на телефоне.

## Прямой маршрут, который блокируется

Обычный VPN отправил бы пакет напрямую:

```text
телефон → VPS → сайт
```

При строгом белом списке соединение `телефон → VPS` не проходит.

## Наш фактический маршрут

```text
Приложение
   ↓
WireGuard на телефоне
   ↓  зашифрованный пакет на 127.0.0.1:9000
FreeTurn на том же телефоне
   ↓  упаковка в разрешённый медиатранспорт
VK TURN/WebRTC
   ↓
free-turn-proxy на VPS
   ↓  извлечённый WireGuard-пакет на 127.0.0.1:51820
WireGuard на VPS
   ↓  расшифрованный исходный запрос
NAT
   ↓
Сайт в интернете
```

### Шаг 1. Приложение создаёт запрос

Браузер, мессенджер или другое приложение формирует обычный интернет-пакет.

### Шаг 2. WireGuard перехватывает и шифрует

Android направляет трафик в VPN-интерфейс. WireGuard шифрует пакет, но отправляет его не на VPS, а на локальный адрес:

```text
127.0.0.1:9000
```

`127.0.0.1` означает «это же устройство». На этом порту ждёт FreeTurn.

### Шаг 3. FreeTurn создаёт внешнюю упаковку

FreeTurn получает уже зашифрованные WireGuard-байты, применяет согласованный профиль `rtpopus` и переносит данные через TURN/WebRTC-сессию VK.

Получается вложение:

```text
[обычный интернет-пакет]
    внутри WireGuard
        внутри FreeTurn/rtpopus
            внутри VK TURN/WebRTC
```

### Шаг 4. Оператор пропускает VK

Первое внешнее соединение телефона направлено к разрешённой инфраструктуре VK, а не напрямую к зарубежному VPS.

### Шаг 5. VPS снимает внешнюю упаковку

`free-turn-proxy` принимает поток, проверяет `obf-key`, снимает транспортную оболочку и передаёт восстановленный WireGuard-пакет локально:

```text
127.0.0.1:51820
```

### Шаг 6. WireGuard на VPS расшифровывает

WireGuard проверяет ключ телефона, расшифровывает пакет и передаёт его сетевой подсистеме Linux.

### Шаг 7. NAT выпускает запрос

NAT заменяет внутренний адрес телефона публичным адресом VPS. Для сайта запрос выглядит пришедшим с VPS.

## Как возвращается ответ

Ответ проходит ту же цепочку наоборот:

```text
сайт
  → VPS/NAT
  → WireGuard на VPS
  → free-turn-proxy
  → VK TURN/WebRTC
  → FreeTurn на телефоне
  → WireGuard на телефоне
  → приложение
```

## Что важно не перепутать

- `127.0.0.1:9000` — локальная передача от WireGuard к FreeTurn на телефоне.
- `127.0.0.1:51820` — локальная передача от free-turn-proxy к WireGuard на VPS.
- телефон не устанавливает прямой WireGuard-сеанс с публичным IP VPS;
- ссылка звонка нужна для доступа к медиатранспорту VK, а не для шифрования данных.
