# 9. Дополнительные телефоны, ноутбук, iPhone и раздача интернета

[← Диагностика](08-troubleshooting.md) · [Оглавление](README.md)

Эта глава отвечает на практический вопрос: как использовать рабочую схему не на одном Android, а на нескольких устройствах.

## Короткий ответ

Да, подключить несколько устройств можно. Самая правильная схема:

```text
каждое активное устройство
        ↓
собственный WireGuard peer
        ↓
собственный FreeTurn-клиент или общий правильно настроенный шлюз
        ↓
VPS
```

Не следует просто копировать один и тот же WireGuard-конфиг на все телефоны.

## Почему каждому устройству нужен отдельный WireGuard peer

WireGuard узнаёт клиента по его публичному ключу. У каждого устройства должны быть:

- собственный приватный ключ;
- собственный публичный ключ;
- отдельный внутренний IP;
- отдельная запись `[Peer]` на сервере.

Пример логики адресов:

```text
Android №1 → 10.66.66.2/32
Android №2 → 10.66.66.3/32
Ноутбук   → 10.66.66.4/32
Шлюз      → 10.66.66.5/32
```

Это только пример. Реальные адреса должны соответствовать вашей серверной конфигурации.

Если два телефона используют одинаковый приватный ключ и один адрес, сервер считает их одним клиентом. Он будет отправлять ответы на последний увиденный endpoint, поэтому связь начнёт перескакивать между устройствами.

## Как выглядит второй Android

```text
Приложения Android №2
        ↓
отдельный WireGuard-профиль
        ↓  Endpoint: 127.0.0.1:9000
FreeTurn на Android №2
        ↓
VK TURN/WebRTC
        ↓
тот же free-turn-proxy на VPS
        ↓
отдельный peer Android №2 в WireGuard
        ↓
интернет
```

Для второго телефона обычно нужны:

1. новая пара ключей WireGuard;
2. новый внутренний IP;
3. новая запись peer на сервере;
4. новый клиентский конфиг;
5. желательно отдельный Client ID FreeTurn;
6. при необходимости отдельная ссылка звонка.

Общими могут оставаться:

- публичный ключ WireGuard-сервера;
- адрес и порт FreeTurn-сервера;
- профиль `rtpopus`;
- серверная инфраструктура.

Общий `obf-key` технически возможен, но ухудшает управляемость: при утечке приходится менять его у всех. Если архитектура сервера позволяет разделять клиентов или экземпляры, лучше делать это постепенно.

## Нужна ли каждому телефону отдельная ссылка звонка

Универсального правила нет. Один звонок иногда способен обслуживать несколько технических потоков, но это повышает:

- число отображаемых участников;
- вероятность CAPTCHA;
- риск ограничений аккаунта;
- сложность диагностики;
- влияние одного проблемного клиента на остальных.

Для небольшой группы сначала можно протестировать общий звонок. Для более предсказуемой эксплуатации удобнее разделять устройства по отдельным звонкам или небольшим группам.

## Упадёт ли скорость

Зависит от схемы подключения.

### Сценарий A: у каждого устройства собственная SIM-карта и собственный FreeTurn-клиент

Скорость не обязана просто делиться на количество телефонов. Каждый телефон имеет собственный радиоканал до оператора.

Но общими узкими местами могут остаться:

- один звонок VK;
- один аккаунт;
- TURN-инфраструктура;
- ограничения на число потоков;
- сервер FreeTurn;
- внешний канал VPS.

Поэтому второй телефон может почти не повлиять на первый, а может вызвать шейпинг, CAPTCHA или обрывы. Это определяется только тестом.

### Сценарий B: все устройства идут через один телефон или один шлюз

Тогда они делят один туннель:

```text
один туннель около 1 Мбит/с
        ↓
телефон + ноутбук + iPhone
        ↓
общая скорость распределяется между активными устройствами
```

Если одновременно что-то загружают три устройства, каждому не гарантируется треть скорости. TCP, потери и фоновые обновления могут сделать распределение ещё хуже.

Такой режим годится для:

- текстовых сообщений;
- почты;
- лёгких сайтов;
- аварийного доступа.

Он плохо подходит для:

- YouTube;
- видеозвонков;
- обновлений ОС;
- облачных резервных копий;
- нескольких активных пользователей.

## Можно ли просто раздать интернет с Android

Иногда — да, но стандартный Android **не гарантирует**, что трафик клиентов точки доступа пойдёт через пользовательский VPN.

Возможны две разные цепочки:

```text
трафик самого телефона → WireGuard/FreeTurn → VPS

трафик ноутбука через hotspot → напрямую к оператору
```

То есть на телефоне заблокированный сайт работает, а на ноутбуке через его точку доступа — нет.

### Как проверить

1. Включите FreeTurn и WireGuard на телефоне.
2. Откройте сервис проверки внешнего IP на телефоне.
3. Запомните адрес: он должен совпадать с VPS.
4. Включите точку доступа.
5. Подключите ноутбук.
6. Проверьте внешний IP на ноутбуке.

Если ноутбук показывает адрес мобильного оператора, его трафик идёт мимо VPN.

### Что требуется для настоящего VPN-hotspot

Обычно нужен один из вариантов:

- функция VPN sharing, встроенная производителем;
- root и приложение, настраивающее NAT/маршрутизацию;
- отдельный Linux-шлюз;
- специальный роутер;
- FreeTurn-клиент непосредственно на подключаемом устройстве.

Для рабочей аварийной системы не стоит начинать с root-раздачи: это добавляет ещё один сложный слой.

## Что делать с ноутбуком

Лучший вариант — запустить FreeTurn и WireGuard прямо на ноутбуке.

```text
Ноутбук
  приложения
      ↓
  WireGuard
      ↓
  локальный FreeTurn
      ↓
  мобильная сеть телефона как обычный доступ
      ↓
  VK TURN → VPS → интернет
```

Телефон в этом случае используется только как модем. Ему не обязательно самому поднимать VPN.

Ноутбуку нужен отдельный WireGuard peer и отдельный конфиг. Нельзя использовать конфиг телефона.

### Почему это лучше раздачи VPN с телефона

- маршрут понятен;
- проще проверить логи;
- нет зависимости от особенностей Android tethering;
- ноутбук не делит VPN-процесс с телефоном;
- можно отдельно менять MTU и число потоков;
- можно остановить ноутбук, не ломая соединение телефона.

## Что делать с iPhone

На iPhone прямой запуск такой схемы сложнее. iOS ограничивает:

- фоновые процессы;
- постоянное выполнение обычных приложений;
- одновременную работу нескольких VPN-компонентов;
- установку собственных Network Extension без подходящей подписи.

Есть три практических пути.

### 1. Совместимый нативный клиент iOS

Это лучший прямой вариант, если существует клиент, совместимый именно с используемой версией FreeTurn-сервера.

Перед использованием нужно проверить:

- поддерживает ли он WireGuard или проксирование WireGuard;
- поддерживает ли нужный профиль обфускации;
- умеет ли работать в фоне;
- как устанавливается и подписывается;
- не требует ли другой серверной реализации.

### 2. Внешний Wi-Fi-шлюз

Самый предсказуемый путь:

```text
iPhone
   ↓ Wi-Fi
ноутбук / мини-компьютер / роутер
   ↓
FreeTurn + WireGuard
   ↓
VK TURN → VPS
```

iPhone видит обычную Wi-Fi-сеть, а вся сложная схема работает на шлюзе.

Минус: все клиенты шлюза делят его скорость.

### 3. Экспериментальная пользовательская среда

Запуск Linux-подобного окружения или неподписанного клиента возможен как эксперимент, но плохо подходит для постоянной связи: iOS может останавливать процесс в фоне.

## Какой шлюз выбрать

Для нескольких устройств удобнее всего небольшой постоянно работающий Linux-компьютер:

- старый ноутбук;
- мини-ПК;
- Raspberry Pi или аналог;
- роутер с подходящей прошивкой, если на нём можно запустить нужные компоненты.

Схема:

```text
мобильный модем / Android hotspot
        ↓
Linux-шлюз с FreeTurn + WireGuard
        ↓
локальная Wi-Fi-сеть
        ↓
Android, iPhone, ноутбуки
```

Перед покупкой оборудования сначала нужно доказать, что FreeTurn-клиент стабильно работает на имеющемся ноутбуке.

## Практическая стратегия

Для небольшой группы устройств:

```text
основной Android → собственный туннель
второй Android   → собственный туннель
ноутбук          → собственный туннель
iPhone           → через отдельный Wi-Fi-шлюз
редко используемые устройства → через тот же шлюз
```

Для десяти телефонов не стоит сразу создавать десятки потоков. Добавляйте устройства по одному и после каждого проверяйте:

- скорость первого клиента;
- скорость нового клиента;
- количество участников звонка;
- CAPTCHA;
- логи FreeTurn;
- WireGuard handshake каждого peer;
- стабильность в течение нескольких часов.

## Чек-лист нового устройства

```text
[ ] Создана новая пара ключей WireGuard
[ ] Выдан уникальный внутренний IP
[ ] Добавлен отдельный peer на VPS
[ ] Создан отдельный клиентский конфиг
[ ] Endpoint клиента указывает на локальный FreeTurn
[ ] Настроен правильный rtpopus/obf-key
[ ] Появился WireGuard handshake
[ ] Растут transfer received/sent
[ ] Внешний IP совпадает с VPS
[ ] Проверена скорость без других клиентов
[ ] Проверена скорость при одновременной работе
```

## Итог

Подключать дополнительные устройства можно, но правильная единица масштабирования — не копия одного файла, а отдельный клиент:

```text
отдельные ключи + отдельный IP + отдельный peer
```

Один общий телефон-шлюз проще, но делит и без того ограниченную скорость. Для Android и ноутбука предпочтительны самостоятельные клиенты. Для iPhone наиболее предсказуем внешний Wi-Fi-шлюз.
